# dexvm-wasm

[`dexvm`](https://crates.io/crates/dexvm) — a DEX VM for Mihon/Tachiyomi
extensions — compiled to `wasm32-wasip1`, with a zero-dependency loader.

Download `dexvm_bridge.wasm` + `dexvm-host.js` from a
[release](https://github.com/Yswag/dexvm-wasm/releases) and you have a
synchronous JSON API for opening an extension APK and crawling it. No VM or
runtime is bundled here; networking belongs to the host.

Not included: UI, bookshelf, reader, or any application logic.

| File | Purpose |
|---|---|
| `dist/` | build output — produced by CI/release, not committed |
| `dexvm-host.js` | WASI subset + `host` imports (ES module, Worker and Node) |
| `dexvm-bridge/` | Rust crate (cdylib) |
| `vendor/dexvm/` | upstream 0.2.0 + [`patches/`](patches/) |
| `test/` | corpus APKs and end-to-end driver |
| `COMPAT.md` | compatibility matrix and corpus policy |

## Usage

```js
import { createDexvm } from './vendor/dexvm-host.js';

const vm = await createDexvm({
  wasmBytes: await (await fetch('./vendor/dexvm_bridge.wasm')).arrayBuffer(),
  http: (reqJson) => proxySync(reqJson), // synchronous, returns JSON
  log: (level, msg) => {},              // optional
});

const { handle, manifest } = vm.call('open', { apkBase64 });
const sources = vm.call('sources', { handle }); // [{ id: "844831…", name, lang, … }]
const page = vm.call('popular', { handle, sourceId: sources[0].id, page: 1 });
```

`vm.call()` is synchronous and throws `DexvmError { kind, message }` on failure.

### Why pin by SHA-256

A release publishes two files that only work as a pair, and the `.wasm` is a
4 MB binary that executes extension bytecode from third-party APKs. Recording
both hashes in your dependency manifest buys two things:

* **Integrity** — you are not loading a substituted or truncated binary from a
  mirror, CDN cache, or a modified copy in someone else's fork.
* **Version lock** — the loader and the wasm share one ABI. A stale loader
  against a newer wasm (or the reverse) fails in ways that look like VM bugs;
  matching hashes make that impossible.

Verify once at build time, or at startup with `crypto.subtle`:

```sh
sha256sum -c SHA256SUMS        # from the release
```

```js
const digest = await crypto.subtle.digest('SHA-256', wasmBytes);
const hex = [...new Uint8Array(digest)].map((b) => b.toString(16).padStart(2, '0')).join('');
if (hex !== EXPECTED_SHA256) throw new Error('dexvm_bridge.wasm checksum mismatch');
```

If you vendor the two files into a locked build and never fetch them at
runtime, the hash is only a one-time supply-chain check.

## Build

```
scripts/build.sh             # cargo build + wasm-opt -Oz + sha256
scripts/release.sh v0.1.0    # same, plus dist/SHA256SUMS and BUILDINFO
node test/run.mjs fixtures   # corpus gate
```

A clean checkout has no wasm: `dist/` is generated by CI on a `v*` tag (and
attached to the release). Plain pushes only upload a build artifact, so the
repository stays binary-free.

Requires `rustup` with the `wasm32-wasip1` target, a host C compiler for build
scripts, and optionally `wasm-opt` (binaryen). Expect ~20 minutes for a clean
build.

Sizes: 5,593,318 B after `cargo build --release`; 3,931,926 B after
`wasm-opt -Oz` (−29.7%).

## ABI

```
alloc(len: usize) -> *mut u8
dealloc(ptr: *mut u8, len: usize)
call(ptr: *mut u8, len: usize) -> u64     // (ptr << 32) | len
```

Request: `{ "op": string, "handle"?: number, ...args }`
Reply: `{ "ok": true, "value": … }` or
`{ "ok": false, "error": { "kind": string, "message": string, "httpError"?: string } }`

The host reads the reply and calls `dealloc(ptr, len)`. Buffers handed back from
`host.http` are allocated through the same `alloc` export and freed by the VM.

### Imports (`host`)

```c
u64 http(const u8 *req, usize len);      // {url, method, headers: [[k,v]], bodyBase64?}
                                         // -> {status, headers, bodyBase64, finalUrl} | {error}
void log(u32 level, const u8 *ptr, usize len);
u64 eval_js(const u8 *ptr, usize len);   // only used by the quickjs replacement
```

`http` must be synchronous. A `{ error }` reply becomes a `code: 0` response and
the message surfaces as `(network: …)` in the failing op's error.

### WASI subset

`clock_time_get`, `random_get`, `fd_write`, `environ_*`, `args_*`, `sched_yield`,
`proc_exit`, `poll_oneoff` (clock subscriptions only, busy wait capped at 2 s).
Other `fd_*` return `EBADF`; `path_*` return `ENOSYS`.

## Operations

| op | arguments | returns |
|---|---|---|
| `open` | `apkBase64`, `prefs?` | `{ handle, manifest }` |
| `sources` | — | `Source[]` |
| `popular` / `latest` | `sourceId`, `page` | `MangaPage` |
| `filters` | `sourceId` | `FilterDef[]` |
| `search` | `sourceId`, `query`, `page`, `filters` | `MangaPage` |
| `details` | `sourceId`, `manga` | `Manga` |
| `chapters` | `sourceId`, `manga` | `Chapter[]` (upstream order) |
| `pages` | `sourceId`, `chapter` | `PageRef[]` |
| `imageUrl` | `sourceId`, `page` | `{ imageUrl }` |
| `imageRequest` | `sourceId`, `page` | `{ url, method, headers }` |
| `fetchImage` | `sourceId`, `page` | `{ url, bytes, mime, base64 }` |
| `preferences` | `sourceId` | `SettingsNode[]` |
| `setPreference` | `sourceId`, `key`, `value` | `{ file, key }` |
| `exportPrefs` | — | `{ "<prefs file>": { key: value } }` |
| `close` | — | `null` |

```ts
type Source = { id: string; name: string; lang: string; baseUrl: string;
                supportsLatest: boolean; nsfw: null };
type Manga = { title: string; author: string; artist: string; description: string;
               genre: string; status: number; thumbnailUrl: string; url: string };
type Chapter = { name: string; url: string; dateUpload: number; scanlator: string };
type PageRef = { index: number; name: string; url: string; imageUrl: string };
type MangaPage = { mangas: Manga[]; hasNextPage: boolean };
type FilterDef = { kind: 'plain'|'header'|'separator'|'text'|'select'|'tristate'|'group';
                   name: string; state: number; options: string[] };
type SettingsNode = { key: string|null; title: string|null; summary: string|null;
                      defaultValue: string|number|boolean|null; enabled: boolean;
                      visible: boolean; kind: string|null; entries: string[];
                      entryValues: string[]; defaultText: string|null;
                      defaultValues: string[]; children: SettingsNode[] };
type Manifest = { packageId: string; appName: string; versionName: string|null;
                  minSdk: number|null; targetSdk: number|null;
                  iconResourceId: number|null; nsfw: null };
```

`sourceId` is a decimal string: extension ids are `i64` and do not survive a
JSON number round-trip.

`fetchImage` resolves the page URL first (the `imageUrl` step some sources
require), then runs the extension's own interceptor chain, returning the bytes
untouched and the last response's `content-type`.

`open`'s `prefs` uses the same shape as `exportPrefs` and is seeded before the
extension reads it: `{ "source_3973269831131863421": { "website_password": "…" } }`.

## Upstream changes

Rust sources untouched. Only `Cargo.toml` — see
[`patches/dexvm-0.2.0-cargo.patch`](patches/dexvm-0.2.0-cargo.patch):

| change | reason |
|---|---|
| drop `quickjs` feature and `rquickjs` | C dependency; replaced by a `register_native` shim calling `host.eval_js` |
| `zip` default-features off, `["deflate"]` | drops zstd/bzip2 |
| `raqote` default-features off | drops text/font-kit |

Two natives are registered from the bridge (`dexvm-bridge/src/shims.rs`):
`Jsoup.parse(InputStream,String,String)` (missing upstream) and the
`app.cash.quickjs.QuickJs` replacement. `compile`/`execute` (QuickJS bytecode)
return `null`.

## Verification

Corpus: 5 APKs from the upstream crate. All open and list sources; ids, langs
and base URLs match the upstream expectations.

| source | mangas | chapters | pages | image |
|---|---|---|---|---|
| MangaPill (en) | 10 | 405 | 24 | 260,462 B `image/jpeg` |
| Comic Fury (all) | 30 | 392 | 1 | 988,598 B `image/png` |

Cold start (`open` + first `sources`): 77 ms and 140 ms. 14 of 15 language
sub-sources of Comic Fury complete the full flow; one has no chapters in its
first three mangas (site data).

The 10 popular sources currently published by the keiyoushi repo (4 Chinese,
2 image-descrambling) fail at `popular` — see `COMPAT.md`. They are ext-lib 1.6
builds; dexvm 0.2.0 implements the 1.5 generation of the API.

## Limitations

* **Panics trap.** `wasm32-wasip1` has no unwinding, so `catch_unwind` is inert.
  The loader converts a trap into `DexvmError { kind: 'trap' }` and marks the
  instance unusable; recovery requires a fresh instance.
* **ext-lib 1.6.x is not supported.** Missing shims: `Json.Default`,
  `DateTimeFormatter.parseCaseInsensitive()`, some `Collection.iterator()`
  paths; several sources also NPE during parsing.
* **`nsfw` is always `null`.** NSFW flags live in the extension index, not the APK.
* **Image `Referer`.** Some CDNs reject requests without one, so `fetchImage`
  and `imageRequest` fall back to the source's `baseUrl` when the extension sets
  none.
* **`imageRequest` is capture-based.** It runs the real interceptor chain but
  records the request at the host boundary and answers with an empty 200.
* **Text filters unsupported.** Upstream `FilterState` carries only name and state.
* **No filesystem.** `path_*` return `ENOSYS`, so preferences are persisted by
  the host via `exportPrefs` / `open.prefs`.

## Maintenance

* The guarantee is "every APK in the corpus passes", not "every extension
  works". Corpus and pins live in [`COMPAT.md`](COMPAT.md).
* Day to day: nothing. Released artifacts are pinned; upstream rebuilds daily
  and do not affect consumers.
* On a breaking upstream change (new Mihon major, or an okhttp/kotlin major):
  add shims, refresh the corpus, tag a release. Budget 1–2 weeks.
* To widen coverage, add one APK at a time and fix until green.
